# Metagraphed Backend Artifact Contracts

Metagraphed v1 is backend-first. The public contract is static JSON under `https://api.metagraph.sh/metagraph/*`; UI work can consume these artifacts later without changing the registry pipeline.

## Contract Rules

- `registry/native/finney-subnets.json` is canonical for active Finney subnet existence.
- `registry/subnets/**/*.json` is canonical for curated public interface metadata.
- `registry/candidates/**/*.json` is discovery-only. Candidates are not verified registry surfaces until promotion.
- `registry/adapters/latest/*.json` stores safe adapter snapshots for subnet-specific public metrics.
- `registry/reviews/maintainer-reviewed.json` stores public-safe maintainer review decisions.
- `schemas-src/**/*.ts` is canonical for public API/artifact component schemas — Zod, registered in `schemas-src/openapi-registry.ts`. It is the ONLY source; `validate:single-schema-source` fails the build if a second one appears (#9830).
- `schemas/*.json` holds the INPUT schemas that validate hand-written registry files (subnet manifests, providers, candidates, saved queries). Those are not published components and stay JSON.
- `/metagraph/openapi.json`, `/metagraph/types.d.ts`, `packages/contract/index.d.ts`, and `generated/metagraphed-client.ts` are generated from the canonical schema and route metadata.
- `public/metagraph/*` files are compact generated projections and should not be edited by hand. R2-only artifacts must not be committed there.
- `dist/metagraph-r2/metagraph/*` is the ignored staging tree for volatile/detail generated projections that are uploaded to R2.
- Artifact contracts carry `storage_tier`: `dual` for compact Git-plus-R2 artifacts, `r2` for volatile/detail artifacts, and `git` for local-only generated support artifacts.
- Health, RPC, adapter, and schema-drift artifacts are operational observations, not protocol authority.
- No secrets, wallet data, PATs, private dashboards, or validator-sensitive flows belong in any public artifact.
- Zod is the AUTHORING source for the backend contract (#9830). JSON Schema remains what is PUBLISHED and what AJV validates against — `openapi.json` is generated from the Zod schemas, never written by hand. This reverses the v1 position that "Zod is not backend contract authority": it was true while components were hand-written JSON, and the two sources drifted for exactly as long as both existed.

## Core Artifacts

- `/metagraph/contracts.json`: current public artifact contract version and artifact map.
- `/metagraph/providers.json`: provider/source registry.
- `/metagraph/providers/{slug}.json`: per-provider detail payload. R2-backed.
- `/metagraph/providers/{slug}/endpoints.json`: endpoint resources for one provider or operator. R2-backed.
- `/metagraph/subnets/{netuid}/wallets.json`: one subnet's declared wallets with their roles, evidence and per-window activity. `owner` is chain-derived from `SubnetOwner` and flagged `chain_derived`; every other role is a human attribution and carries the `source_urls` that prove it **in the response**, so a consumer never has to make a second call to check an attribution it is about to repeat. TAO and alpha activity are reported on separate legs and never summed. An empty list means nothing has been attributed for this subnet, which is not the same as nothing existing. Served live at `GET /api/v1/subnets/{netuid}/wallets`.
- `/metagraph/subnets/{netuid}/owner-cut.json`: one subnet's owner-cut accrual and what became of it. The cut is 18% (`SubnetOwnerCut` is 11796/65535, not one sixth) and the storage item is unset on chain, so the effective share is the runtime default and is labelled reconstructed. It is paid as **stake** rather than a liquid balance, so absence of flow evidence resolves to `unresolved` rather than to `held-as-stake`. The disposition buckets are not balanced to tie: `residual_alpha` reports what is unaccounted for. Served live at `GET /api/v1/subnets/{netuid}/owner-cut`.
- `/metagraph/entities.json`: curated address-label registry — one entry per ss58 that has cleared `docs/nametag-evidence-bar.md`, each carrying the `source_urls` that prove the attribution, plus the money-map roles (`treasury`, `burn`, `payment-collector`, `multisig`) and the `netuid` a subnet-scoped label belongs to. There is no `owner` category: subnet ownership is chain-derived from `SubnetOwner` and is never hand-declared. An empty list is the honest state of a curated layer, not a cold store.

- `/metagraph/subnets/{netuid}/volume.json`: schema for rolling 24h buy/sell alpha volume (unsigned alpha and TAO totals for StakeAdded vs StakeRemoved, plus event counts), a sentiment indicator derived from it (net_volume_alpha, a bounded sentiment_ratio, and a bullish/bearish/neutral label), and a vol_mcap_ratio turnover figure (total_volume_tao over the live economics tier's alpha_market_cap_tao, null when that external input is unavailable), served live from the same account_events store stream as stake-flow at `GET /api/v1/subnets/{netuid}/volume` (no static file).
- `/metagraph/subnets/{netuid}/ohlc.json`: schema for OHLC price/volume candlesticks (#5655, Phase 1 of the OHLC epic #5304) — open/high/low/close/volume candles bucketed by `?interval=1h|1d` (default `1h`), shaped in pure JS (`buildSubnetOhlc`, `src/subnet-ohlc.ts`) from raw StakeAdded/StakeRemoved rows over the same `account_events` stream as `volume`/`stake-flow`: each row is one executed trade, price = `amount_tao / alpha_amount`. `?days=` bounds the lookback window (default 90, max 365). Empty buckets are gaps, never synthesized flat candles. The root subnet (netuid 0) has no AMM pool — 1:1 TAO, no price impact — so it returns an empty `candles` array with `root_excluded:true` instead of a meaningless flat line. **An EMPTY `candles` is a measurement, a FAILED read is not** (#10312): a decline carries `degraded.reason: unavailable` with a NULL `candle_count`, where a genuinely untraded window and root both carry `0` and no marker. That distinction is load-bearing here rather than theoretical — the lakehouse query behind this route was measured at 7.3s–24.4s against a 15s timeout (2026-08-16), so a failed read is routine, and all three surfaces previously published it as `candle_count: 0`, which reads as a subnet that has never traded. **`candle_count` is a FLOOR when `window_truncated` is true**: the tier reads `MAX_CANDLES + 1` rows and the surplus row is the truncation signal, because the aggregate that would count the whole window is rejected as `40015: scan budget exceeded` on any window wide enough to need it. At `1h` buckets the cap binds from ~83 days — inside the default 90-day window. Served live at `GET /api/v1/subnets/{netuid}/ohlc` (no static file).
- `/metagraph/subnets/{netuid}/stake-quote.json`: schema for a read-only constant-product stake/unstake slippage quote (expected alpha/TAO out, spot vs effective price in TAO per alpha, and price-impact percent) for a `?amount=`/`?direction=stake|unstake` swap against the subnet's economics-tier AMM pool reserves (tao_in_pool_tao, alpha_in_pool), computed live at `GET /api/v1/subnets/{netuid}/stake-quote` (no static file). Pure math — no chain write or custody; the root subnet (netuid 0) returns a 1:1, zero-impact quote, and an amount over 1000× the relevant reserve returns 422.
- `/metagraph/subnets/{netuid}/validator-economics.json`: schema for what a validator permit costs on one subnet and whether holding one earns, computed live at `GET /api/v1/subnets/{netuid}/validator-economics` (no static file). Carries the permit floor (the `total_stake` needed to hold a permit, where `total_stake = alpha + tao_weight * root` is the quantity the chain threshold tests) and the earning floor (where the smallest permit-holder with dividends sits, a median ~7x higher — a permit is not income), each priced in TAO against the AMM pool reserves plus the registration burn; validator set composition as three separate counts (permitted / active / earning); open slots and whether the cap binds; the take distribution across permit-holders including the sorted vector; the emission-gate state and daily TAO inflow; and the live sudo-settable StakeThreshold/TaoWeight the floors were derived against. Root stake is not split, so `root_tao_to_clear_threshold` clears the threshold on every registered subnet at once. Every derived field is nullable and degrades with a stated `degraded_reason` rather than reporting a confident zero.
- `/metagraph/subnets/{netuid}/validator-economics-history.json`: schema for the OBSERVED validator-economics series for one subnet over a 7d/30d/90d window (default 30d), computed live at `GET /api/v1/subnets/{netuid}/validator-economics/history` (no static file). Each daily point carries the permit floor and earning floor in ALPHA — the smallest stake that actually held a permit, and that actually earned, that day — plus the validator set composition as three counts and the emission-gate state with daily TAO inflow. The floors are read off each snapshot rather than re-derived, because StakeThreshold is sudo-settable and re-running today's threshold against a historical day would show a flat line across the governance change that moved it. TAO cost and `cap_binding` are deliberately absent: a historical cost needs the pool reserves as they were, and `subnet_snapshots` carries no historical `max_validators`.
- `/metagraph/validators/economics.json`: schema for every subnet ranked by what it costs to become an EARNING validator there, computed live at `GET /api/v1/validators/economics` (no static file). One row per subnet with the same fields as the per-subnet artifact, sortable by `earning_floor_cost_tao` (default, cheapest first), `permit_floor_cost_tao`, `permit_to_earning_multiple`, `tao_inflow_per_day` or `validator_headroom`, and filterable on `emission_gate_open` / `cap_binding` — omitting a filter means BOTH, which is not the same as false. Every subnet the ranking drops appears in `excluded` with a reason. Derived from one cross-subnet neuron scan plus one economics-artifact read rather than 128 per-subnet round trips; the registration burn is excluded from the ranking because it is a live per-subnet read and immaterial to the order.

- `/metagraph/validators.json`: schema for the network-wide validator/operator footprint leaderboard (validator-permit identities grouped across all current subnet memberships; per-membership stake/emission remains scoped to `subnets[]`), served live from the `neurons` store tier at `GET /api/v1/validators` (no static file). Same cadence as every other route reading the `neurons` tier: the poller Container's `metagraph` job on a **15-minute** loop (`METAGRAPH_POLL_SECS`, default 900), which POSTs a full snapshot to `/api/v1/internal/neurons-sync`. This is no longer the daily box timer `metagraphed-refresh-metagraph.timer` (`23 5 * * *` UTC), retired 2026-08-03 with the box -- so a `captured_at` more than ~45 minutes old is a stalled lane, not ordinary cadence, and the neurons-staleness watchdog alarms on exactly that threshold.
- `/metagraph/validators/operators.json`: schema for the compact website-facing operator directory, served live from the complete `neurons` snapshot at `GET /api/v1/validators/operators` (no static file; mainnet only). Hotkeys group only when each has exactly one observed owner account and that owner is shared; declared names never establish membership. `operator_id` is stable within the response network, independently of identity names or the stake-ranked primary hotkey. `ownership_basis` distinguishes observed single-coldkey agreement from ambiguous or unknown ownership, both of which stay hotkey-scoped. This evidence does not verify a brand or organization. Both metadata fields are optional for older cached responses; missing evidence must be treated as unknown. The existing `coldkey` remains the primary hotkey's source-selected owner, which is common to all members only for a single-coldkey group. Each operator retains the primary hotkey, optional multi-key breakdown, existing stake/emission and APY fields, memberships, UID count, take range, stake dominance, capture time, and block number. `nominator_count` is a count of distinct nominator accounts (coldkeys) for a singleton, never people or positions; it is null when unavailable or for any multi-key group because per-hotkey counts cannot establish a deduplicated operator total or complete cross-key coverage. The response is an HTTP/SSR transport projection of `/api/v1/validators`; the richer route remains the public record for callers that need per-hotkey memberships and emission-rate estimates. It uses the same 15-minute neuron-pass cadence described above and is edge-cached against the newest completed pass rather than a wall-clock bucket.
- `/metagraph/accounts.json`: schema for the site-wide accounts leaderboard — every currently-registered hotkey (miners included, not just validator-permit ones) grouped across all current subnet memberships with a validator/miner UID breakdown, served live from the `neurons` store tier at `GET /api/v1/accounts` (no static file). No "Free"/spendable-balance or "Total" column — no balance-tracking tier exists to source them. The collection-level counterpart to `/api/v1/validators`.
- `/metagraph/accounts/directory.json`: compact website projection of the same complete neuron snapshot, served live at `GET /api/v1/accounts/directory` (no static file). It aggregates the snapshot once and returns fixed top-20 stake, emission, and subnet-reach rankings together, plus the complete TAO-priced registered-stake denominator used for honest network-wide share labels. The independently sortable `/api/v1/accounts` contract remains unchanged.
- `/metagraph/top-holders.json`: schema for the balance-based top-holder leaderboard (#6741/#6743) — the coldkey/balance-centric counterpart to `/metagraph/accounts.json` above, adding the Free/Delegated/Total columns that route explicitly cannot derive — served at `GET /api/v1/accounts/top-holders` (no static file) from TWO tiers selected by sort (#9469). `net_flow_7d`/`net_flow_30d`/`net_flow_90d` (#6886/#6887) — cross-subnet stake flow (StakeAdded minus StakeRemoved) over each window — are **live**: the `top-holders-flow` projection lane (`src/top-holders-flow-tier.ts`) recomputes all three from `chain.account_events` in one daily scan and writes `metagraph/projections/top-holders-flow.json`, so `captured_at` advances on those sorts. Unlike the balance columns these are signed (a real net outflow is negative, not zeroed). `free_tao`/`delegated_tao`/`total_tao` are **composed live** from the store by the same lane (`src/top-holders-holdings.ts`, #9545): `free_tao` from `account_balances` (#9483/#9501), `delegated_tao` by pricing each `nominator_positions` row against the `hotkey_alpha` per-`(hotkey, netuid)` pool total (#9512) and that netuid's `alpha_price_tao` from `subnet_snapshots`, and `total_tao` as their sum ranked across the FULL tables rather than over the other two sorts' capped rows. Each holdings sort is served live **only while its producer's most recent pass is recorded complete** (`src/account-balances-completeness.ts`, `src/hotkey-alpha-completeness.ts`), because ranking over a partially-loaded ledger returns the largest values _present_ rather than the largest that _exist_ — a well-formed leaderboard quietly missing real top holders. - `/api/v1/validators/{hotkey}/nominators`: fetch the nominator list for one validator. **TWO BASES, and they answer different questions** (#9617). `?basis=flow` (the default, unchanged) is who has staked to it across every subnet it operates in over a `?window=7d|30d|90d`, ranked by `?sort=net_staked|gross_staked|last_activity`, `?limit`/`?offset` paginated, `?coldkey=` narrows to one nominator's own flow — live from the `account_events` StakeAdded/StakeRemoved stream, so it CANNOT see anyone who staked before the window and has not touched the position since. `?basis=positions` reads the `nominator_positions` ledger instead: every account currently holding a position through this hotkey, dormant or not, valued as `share_fraction x hotkey_alpha.total_alpha` against the latest complete pass. `window` and `sort` are REJECTED on this basis rather than ignored — they describe a flow over time and there is no flow here, and silently accepting them would return a differently-ordered list under a parameter the caller believes took effect. **No cross-subnet alpha total appears anywhere on the positions basis**: each subnet's alpha is a different token (#8803), so a nominator is ranked by `subnet_count` then by `largest_position.alpha`, which carries the netuid that gives it a unit. ## Change-Feed Webhooks + SSE

metagraph.sh regenerates its dataset on an event-driven publish — on each human-input registry merge, plus a daily floor (ADR 0007) — so the realtime surface is a **change feed**: a notification within seconds of each publish, not a sub-second tail. These routes live outside the artifact contract (dynamic, KV-backed) and degrade to `503 webhooks_unavailable` when the `METAGRAPH_CONTROL` KV binding is absent.

- `POST /api/v1/webhooks/subscriptions` — register `{ url, filters?: { netuids?: integer[], kinds?: ("subnets"|"artifacts")[] }, secret? }`. The `url` must be a public `https://` endpoint (private/loopback/link-local hosts and non-default ports are rejected). Returns `{ id, secret, ... }` once; the secret is never echoed again.
- `GET /api/v1/webhooks/subscriptions/{id}` — fetch a subscription's public view (no secret), including a `delivery` health summary (`status` `ok`/`retrying`/`dead_letter`, `pending`/`dead_letter` counts, and a `last_failure` with attempt count, reason, and next-attempt time).
- `DELETE /api/v1/webhooks/subscriptions/{id}` — delete; requires the secret in the `x-metagraph-webhook-secret` header.
- `GET /api/v1/events` — thin SSE change feed: emits the current change snapshot (derived from `changelog.json` + the KV `latest` pointer) as one `event: snapshot`, with `retry: 300000` advising a 5-minute reconnect. There is no value in holding a connection open between publishes.

At publish time the dispatcher reads `changelog.json`, matches each subscription's filters, and `POST`s the change event signed with `HMAC-SHA256` (hex) over the raw body in the `x-metagraph-signature` header. Each delivery also carries `x-metagraph-event-id` (stable per event content) and `x-metagraph-idempotency-key` (stable per subscription + event), so subscribers can dedupe retries safely.

Delivery is **at-least-once**. Within a run a transient failure (network/timeout/5xx/429) is retried with short backoff; if it still fails it is parked per-(subscription, event) under the `webhooks:delivery:<id>:<event_id>` KV prefix and re-attempted on subsequent publish runs with bounded exponential spacing (5 min → 12 h). Each publish redelivery sweep is budgeted to a limited key sample, 64 attempts per run, and 8 attempts per subscription. After 8 failed rounds — or on a deterministic rejection (4xx/redirect) — the delivery becomes a dead letter, surfaced via the `delivery` summary on GET. Successful (re)delivery clears the parked record. Parked records (like subscriptions) auto-expire after 180 days. The SSRF guard is best-effort and cannot prevent DNS rebinding; the dispatcher runs on GitHub-hosted runners with no access to the project's network, which bounds the residual risk.

## Remote MCP Server (AI agents)

`POST /mcp` is a stateless [Model Context Protocol](https://modelcontextprotocol.io) server (Streamable HTTP transport, JSON-RPC 2.0) that exposes the registry to AI agents (Claude Desktop/Code, Cursor, autonomous agents). It is read-only, so there is no session id, Durable Object, or server-initiated stream; `GET /mcp` returns `405`. The handler (`src/mcp-server.ts`) is dispatched before the read-only method gate (it is POST-only, like the RPC proxy) and reuses the exact R2/ASSETS artifact resolution via injected readers, so MCP tools and REST routes always agree.

Tools (thin wrappers over the artifact contract): `search_subnets`, `find_subnets_by_capability`, `get_subnet`, `get_subnet_health`, `list_subnet_apis`, `get_api_schema`, `get_agent_catalog`, `get_best_rpc_endpoint` (live-health-filtered), `registry_summary`, the AI-layer pair `semantic_search` (vector/meaning-based discovery) + `ask` (grounded RAG Q&A with citations), and the goal-shaped pair `find_subnet_for_task` (plain-language task → callable subnets, ranked semantically when AI is present, by keyword otherwise) + `how_do_i_call` (one subnet, by netuid or slug → concrete call instructions: base URL, auth, schema pointer, health). The two AI tools require the VECTORIZE + AI bindings and degrade to a graceful `isError` result (pointing at the keyword tools) when the AI layer is unavailable. `tools/call` returns the MCP result envelope (`content[]` text + `structuredContent`); argument and artifact failures degrade to an `isError: true` result rather than a transport error. The server is validated by `npm run validate:mcp` (lifecycle + one `tools/call` per tool against a cold local env) and smoke-checked live by `scripts/smoke-live-api.ts`. The endpoint is excluded from the `validate-api` route-count invariant and is added to `assets.run_worker_first`.

`serverInfo.version` is the MCP server's own **SemVer** (`MCP_SERVER_VERSION` in `src/mcp-server.ts`, also surfaced in the generated `server-card.json`) — deliberately distinct from the date-based `CONTRACT_VERSION` (the REST/data contract), since the tool surface is a separate public contract agents depend on. Bump policy: **add a tool / additive field → minor**; **change or remove a tool's I/O → major**; behavioral-only fix → patch. `validate:mcp` asserts `serverInfo.version` is SemVer and matches the constant.

## AI Search + Ask (semantic + RAG)

Two **out-of-contract dynamic routes** (special-handled like `/api/v1/events`, so they are not in `API_ROUTES`, OpenAPI, or the `validate-api` route-count invariant) power natural-language discovery, backed by Workers AI + a Vectorize index:

- `GET /api/v1/search/semantic?q=&limit=` — embeds the query (`@cf/qwen/qwen3-embedding-0.6b`, 1024-dim) and returns the nearest registry entries `{ score, type, netuid, slug, title, subtitle, url }` (limit ≤ 20). Vector search, so it matches intent without exact keywords.
- `POST /api/v1/ask` — body `{ question }`. Retrieves the top-6 registry entries and prompts `@cf/meta/llama-4-scout-17b-16e-instruct` with a cite-only system prompt, returning `{ question, answer, citations[], context_count, model }`. The answer is grounded in registry context and cites sources as `[n]`.

Both live in `src/ai-search.ts`, return the standard `{ ok, schema_version, data, meta }` envelope, and are gated three ways: the `METAGRAPH_ENABLE_AI` kill-switch, the presence of the `AI` + `VECTORIZE` bindings (absent in local/CI → `503 ai_unavailable`), and the `AI_RATE_LIMITER` binding (20 req/60s per client IP; absent → allow). Hard caps bound cost: result/context size and a 1000-char question limit. The Vectorize index (`metagraphed-registry-v2`, 1024-dim/cosine) is kept warm by a daily embedding-sync cron (`37 3 * * *`) that diffs the `search.json` index against a content-hash manifest in KV and re-embeds only the deltas. Response shapes are validated by `npm run validate:ai` (disabled→503, stubbed-enabled→200 against `schemas/ai/*.schema.json`, negatives + rate-limit); see ADR 0003.

## Routes served but previously undocumented (#9967)

Three routes were served in production while absent from `openapi.json`, each one **named in an MCP tool's own description** — so agents were being pointed at paths the published contract did not describe. A route with no spec entry is also silently skipped by `scripts/check-response-conformance.ts`, so none of them could drift, because nothing checked them.

- `GET /api/v1/webhooks/subscriptions/{id}` and `GET /api/v1/alerts/triggers/{id}` are now registered, with the artifact contracts above. Both return the standard `{ ok, schema_version, data, meta }` envelope.
- `POST /api/v1/graphql` is **deliberately not** in this contract, and that was decided on evidence rather than left open. It answers with `content-type: application/graphql-response+json` and a bare `{ data, errors }` body — the GraphQL-over-HTTP protocol, not this contract's envelope — and carries neither an `ETag` nor an `x-metagraph-contract-version` header. Registering it would publish a response shape production does not serve. Its schema is introspectable through the endpoint itself, which is the document that describes it; `src/mcp-route-map.ts` records that reason against the `query_graphql` tool so the gap stays explained rather than merely absent.
